# ADR-0008 — انضباط گیت (Git Discipline)

وضعیت: پذیرفته‌شده · وابسته به: ADR-0006 (دروازهٔ صفر-رد)، ADR-0007 · قواعد: `AGENTS.md` ← «انضباط گیت» (G1–G15)

## زمینه
- CI تازه سبز شده و ۶۳۱ تست روی PostgreSQL واقعی اجرا می‌شود؛ حالا هر کامیتِ قرمز یک بدهی پنهان است. نرم‌افزار حقوقی «سبزِ بی‌اجرا» را نمی‌پذیرد (ADR-0006)؛ همین منطق برای **تاریخچه** هم لازم است: هر کامیت باید نقطه‌ای باشد که بشود به آن برگشت.
- کارهای پرریسک (مهاجرت پایگاه، `registry.ts`، تاریخ/محاسبات حقوقی، CI) اگر خراب شوند هزینه‌شان بالاست؛ بدون نقطهٔ برگشتِ نام‌دار، «برگشت» یعنی حدس‌زدنِ کامیت درست.
- «قانون آهنین» (تست موجود تغییر نمی‌کند) تا امروز فقط یک جمله در دستور کار بود؛ چیزی جلوی ضعیف‌کردن یک تست برای سبز شدن را نمی‌گرفت.
- تجربهٔ همین پروژه: شکست اول CI به‌خاطر یک annotation گمراه‌کننده بد تشخیص داده شد (ADR-0007). قاعده‌ای که ماشین بسنجد از قاعده‌ای که فقط خوانده شود قابل‌اعتمادتر است.

## تصمیم
1. **قواعد G1–G15 در AGENTS.md** (کامیت بعد از هر ماژول سبز؛ ممنوعیت کامیت قرمز؛ دورزدن‌های ممنوع؛ قانون آهنین؛ قالب پیام؛ نبودن اسرار/خروجی ساخت؛ یک کامیت یک ماژول؛ تگ‌های `pre-risk/*` و `green/*`؛ تغییرناپذیری تگ و تاریخچهٔ پوش‌شده؛ پچِ قابل‌اثبات؛ توقف در CI قرمز).
2. **اجرای خودکار با توابع خالص** در `tooling/git-discipline.ts` (۴۱ تست در `tooling/git-discipline.test.ts`، شامل مخزن گیتِ موقت و اجرای واقعی هوک‌ها):
   - `commit-msg`: قالب پیام؛ تغییرِ تستِ موجود ⇒ نیازمند `Test-Change-Approved`؛ مسیر پرریسک ⇒ نیازمند `Risk-Tag` که **باید تگِ حاشیه‌دارِ موجود و پیشینِ HEAD** باشد؛ دو ماژول ⇒ `Multi-Module`؛ کاهش `MIN_PASSED_TESTS` ⇒ `Gate-Floor-Lowered`.
   - `pre-commit`: نبودن اسرار و فایل‌های ممنوع؛ `.skip/.only/xit` در تست؛ سپس `tsc` ← `eslint` ← دروازهٔ صفر-رد. کامیت **فقط‌مستند** از دروازه معاف است.
   - `pre-push`: ردِ non-fast-forward، حذف ref، تگ سبک، نام تگِ خارج از الگو، جابه‌جایی تگِ پوش‌شده؛ درخت کثیف؛ و دروازهٔ کامل پیش از پوش شاخه.
   - `check-range <a..b>`: لینت پیام یک بازه (برای CI/بازبینی).
   - نصب: `node tooling/git-discipline.ts install` (یک `git config core.hooksPath tooling/git-hooks`)؛ `doctor` وضعیت را می‌سنجد.
3. **فهرست مسیرهای پرریسک یک‌جا و همگام:** `isHighRiskPath` با `docs/high-risk-areas.md` یک آزمونِ همگامی دارد؛ اگر کسی مسیری را فقط در یکی اضافه کند آزمون قرمز می‌شود. افزودهٔ این ADR: `.github/workflows/`، `tooling/ci-tests.ts`، `tooling/git-discipline.ts`، هوک‌ها و `vitest.config.ts` هم پرریسک‌اند (دروازه را ضعیف‌کردن = همهٔ تضمین‌ها را از بین‌بردن). تست و README هیچ‌گاه تگ نمی‌خواهند.
4. **دو خانوادهٔ تگ:** `pre-risk/YYYYMMDD-slug` (نقطهٔ برگشتِ پیش از تغییر) و `green/slug` (نشانِ «CI این را سبز دید»). تگ همیشه حاشیه‌دار و پس از پوش تغییرناپذیر است.

## جایگزین‌های ردشده
- **فقط متن در AGENTS.md:** عاملِ خسته یا عجول آن را رد می‌کند؛ قاعدهٔ اجرانشده پیشنهاد است.
- **`husky`/`lint-staged`/`commitlint`:** وابستگی خارجیِ تازه (قاعدهٔ ۸)؛ نیازی نیست: `core.hooksPath` و Node با حذف نوع کافی است.
- **اجرای دروازه در هر کامیتِ مستند:** ۴۵ ثانیهٔ بی‌فایده؛ کامیت‌های فقط‌مستند (و فقط آن‌ها) معاف‌اند.
- **تگ‌های سبک یا شمارهٔ نسخه (`v1.0`):** معنای «برگشت» نمی‌دهند و جابه‌جاییشان بی‌ردپاست.
- **ممنوعیت مطلق `amend`:** روی کامیتِ محلیِ پوش‌نشده بی‌خطر و مفید است؛ مرز «پوش‌شده» است.

## پیامدها و محدودیت‌ها (صادقانه)
- **هوک محلی دورزدنی است** (`--no-verify`، کلونِ بدون `install`). دروازهٔ واقعی CI و Branch protection است. **کارِ باز برای مالک:** (الف) `verify` را الزامی کنید؛ (ب) پیشنهاد: گامی در `ci.yml` که `check-range` را روی کامیت‌های هر PR اجرا کند — من `ci.yml` را برای این کار تغییر ندادم، چون ورک‌فلوِ تازه‌سبز را بدون امکان اجرای واقعیِ GitHub Actions نباید دست‌کاری کرد.
- `Risk-Tag` فقط **وجود، نوع و نسب** تگ را می‌سنجد؛ اینکه تگ واقعاً «پیش از اولین ویرایش» زده شده از روی تاریخچه قابل اثبات نیست (انسان بازبینی می‌کند).
- `pre-commit` تست را روی **درخت کاری** اجرا می‌کند، نه روی ایندکس؛ تغییر مرحله‌بندی‌نشده هشدار می‌گیرد (`git stash --keep-index`).
- هوک‌ها Node ≥ ۲۲٫۱۸ می‌خواهند (همان نیازِ `ci-tests.ts`).
- پچ‌ها (`public/deliverables/*.patch` در تحویل‌های قدیمی) از این پس در مخزن کامیت نمی‌شوند (G13): پچِ کامیت‌شده در همان کامیت جا نمی‌گیرد و تاریخچه را پر می‌کند.
