# ADR-0038 — tooling م۳‑ه‑۳‑ز: پاک‌سازیِ خانوادهٔ مهاجرتِ تسویه و نگهبانِ راستیِ ارجاع‌های مستنداتِ زنده

وضعیت: پیشنهادی (فقط مستند، آزمون و حذفِ یک اسکریپتِ منسوخ؛ هیچ کدِ تولیدیِ `src/` عوض نمی‌شود) · وابسته به: ADR-0033 (bootstrap)، ADR-0034 (CLIِ مهاجرت)، ADR-0037 (تحویل ۰۰۳۷ «گام بعد ۱»).

## زمینه
ADR-0034 «CLIِ رسمیِ مهاجرت» را ساخت و `tooling/smoke/settlement-migrate.ts` را «منسوخ» اعلام کرد؛ خودِ آن فایل می‌گوید «تا به‌روزشدنِ README/ADRهای قدیمی می‌ماند و برش‌های بعد حذفش می‌کنند». سه برش (۰۰۳۵ تا ۰۰۳۷) آن را شروع نکردند. خوانشِ مستنداتِ زنده (نه فرض) چند ناهمخوانیِ واقعی نشان داد:

1. `settlement-bootstrap/README.md` در «محدودیت‌ها» می‌گوید «CLIِ رسمیِ مهاجرت نیست (`tooling/smoke/settlement-migrate.ts` موقتی است)». **نادرست است**؛ `npm run settlement:migrate` رسمی و آزموده است (ADR-0034) و دودیِ `settlement-next.mjs` هم از آن استفاده می‌کند.
2. `settlement-runtime/README.md` می‌گوید «به `src/app` و `/api/health` وصل نیست (م۳‑ه‑۳)» و `settlement-host/README.md` می‌گوید «به `src/app` وصل نیست (م۳‑ه‑۳‑ب)». **نادرست است**؛ `src/instrumentation.ts` ← `instrumentation-node.ts` ← `settlement-bootstrap` و پروب‌های `src/app/api/health/{live,ready,startup}/route.ts` (ADR-0033) آن را وصل کرده‌اند. (هر دو ماژولِ پایین‌دستی خودشان به Next وصل نیستند؛ این بخش درست می‌ماند و روشن‌تر نوشته می‌شود.)
3. هیچ مکانیسمی جلوی تکرار را نمی‌گیرد: فایلی حذف یا جابه‌جا شود و README به آن اشاره کند، خطایی نیست؛ برعکس، مستندِ اشاره‌کننده یک فایلِ منسوخ را «زنده» نگه می‌دارد (همین اتفاق برای smoke افتاد).

مستندِ دروغ در این پروژه هزینهٔ واقعی دارد: عاملِ بعدی بر اساس «CLIِ رسمی نیست» ممکن است ابزارِ دوم بسازد، یا بر اساس «وصل نیست» سیم‌کشیِ دوباره.

## اندازه‌گیری پیش از ساخت (پایه `6ef97e7`)
- دروازهٔ صفر-رد روی PostgreSQL واقعی (۱۸٫۷، UTF8): ۴۱۱۳ سبز، ۰ رد، ۱۶ todo، ۱۶۰ فایل (برابرِ گزارشِ تحویل ۰۰۳۷).
- پویشِ اکتشافیِ ارجاع‌های بک‌تیکیِ مستنداتِ زنده (۱۶۷ ارجاعِ فایل/پوشه): بدونِ بررسیِ ماژول‌های برنامه‌ریزی‌شده ۱۰ ارجاعِ معلق دیده شد؛ **هیچ‌کدام دروغِ واقعی نبود**: ۹ مورد `src/modules/<ماژولِ آیندهٔ registry>/` در `high-risk-areas.md` و ۱ مورد پسوندِ تنها (`.ts`). یعنی سه ناهمخوانیِ بالا را **پویشِ مسیر نمی‌گیرد** (جمله‌ای‌اند، نه مسیر)؛ نگهبان فقط آن‌چه ماشین می‌تواند بسنجد را قفل می‌کند و ادعای بیشتری نمی‌کند.

## تصمیم ۱ — سه اصلاحِ README (هر ماژول یک کامیت، G7)
فقط جمله‌های نادرست عوض می‌شوند؛ هیچ ناوردا/قراردادی عوض نمی‌شود. ADR/یادداشتِ تحویل/task **ویرایش نمی‌شوند** (تاریخچه‌اند و در زمانِ خودشان درست بودند؛ ADR-0034 صریح می‌گوید «تا امروز تنها ابزار smoke بود»).

## تصمیم ۲ — حذفِ `tooling/smoke/settlement-migrate.ts`
جایگزینِ رسمی، آزموده‌شده و همان رفتار (CLIِ ADR-0034، با آزمونِ فرایندِ واقعی) را دارد؛ هیچ آزمون/کد/اسکریپتِ دیگری آن را نمی‌خواند (`grep`: فقط README/ADR/یادداشتِ تاریخی و یک توضیح در `settlement-next.mjs`). این فایل یک آزمون نیست؛ قانونِ آهنین (G4) به آن مربوط نیست. `settlement-next.mjs` (دودیِ فرایندِ واقعی) می‌ماند.

## تصمیم ۳ — آزمونِ `tooling/docs-path-refs.test.ts` (نگهبان)
روی «مستنداتِ زنده» (`AGENTS.md`، `docs/{known-pitfalls,high-risk-areas,glossary}.md`، README هر ماژول):
- هر مسیرِ فایل/پوشه در بک‌تیک (و هر مسیرِ ریشه‌دار در بلوکِ کد) باید در مخزن باشد. مسیرِ ریشه‌دار (`src/`، `tooling/`، `docs/`…) **دقیق** سنجیده می‌شود؛ نامِ کوتاه (`registry.ts`، `pg/migrations.ts`، `adr/`) به‌صورت پسوندِ مسیر یا نسبت به پوشهٔ همان مستند (سهل‌گیرتر عمداً).
- **استثنا فقط از registry:** `src/modules/<نام>/` وقتی `<نام>` در `src/modules/registry.ts` (منبعِ حقیقتِ لایه‌ها) اعلام شده باشد. فهرستِ دستیِ سفید نمی‌نویسیم؛ ماژولِ برنامه‌ریزی‌شده که از registry برود، ارجاعش خودکار معلق می‌شود. فقط خودِ پوشه معتبر است، نه فایلِ زیرِ آن.
- هر `npm run <نام>` باید در `package.json` → `scripts` باشد.
- حذفِ smoke و وجودِ CLIِ رسمی (`settlement:migrate`) و استفادهٔ دودی از آن قفل می‌شود.
- پویشگر تابعِ خالص است (درخت و اسکریپت‌ها تزریقی)؛ ۱۴ آزمونِ ساختگی نقض و مثبتِ کاذب را می‌سنجد؛ آزمونِ «تهی‌نبودنِ پویشگر» (≥ ۱۵ مستند، ≥ ۱۰۰ ارجاع) جلوی سبزِ بی‌معنا را می‌گیرد.

## گزینه‌های ردشده
- **پویشِ ADR/یادداشت/task:** تاریخچه‌اند؛ ارجاع به فایلِ حذف‌شده در آن‌ها درست است. پویش‌شان هزاران مثبتِ کاذب یا فهرستِ سفیدِ بی‌پایان می‌سازد.
- **فهرستِ سفیدِ دستیِ ماژول‌های آینده:** خودش رانش می‌کند؛ registry همین اطلاعات را دارد.
- **تطبیقِ معنایی («وصل نیست» ← بررسیِ سیم‌کشی):** ناممکن/شکننده؛ نباید وانمود کنیم آزمون آن را می‌گیرد. مسئولیتِ جمله‌ها با بازبینِ انسانی می‌ماند؛ در `known-pitfalls.md` ثبت شد.
- **حذفِ `settlement-next.mjs`:** هنوز تنها دودیِ فرایندِ واقعی (`next start` + SIGTERM) است و ADR-0033 به آن تکیه دارد.

## پیامدها و محدودیت‌ها
- از این پس حذف/جابه‌جاییِ فایلی که مستندِ زنده به آن اشاره می‌کند، همان کامیت را قرمز می‌کند و مستند باید همان‌جا اصلاح شود.
- نامِ کوتاه سهل‌گیر است: `index.ts` با هر `index.ts`ی در مخزن درست می‌شود. این مثبتِ کاذبِ منفی (ارجاعِ غلطِ نامِ کوتاه) را نمی‌گیرد؛ پذیرفته شد چون نامِ کوتاه در README رایج است و سخت‌گیریِ بیشتر مثبتِ کاذبِ بسیار می‌سازد.
- spanهایی با فاصله/glob/`<…>`/`…` عمداً مسیر شمرده نمی‌شوند (الگو یا فرمان‌اند).
- فقط ارجاعِ **وجود** را می‌سنجد، نه اینکه جمله‌ای دربارهٔ آن فایل درست باشد.
- سه ناهمخوانیِ بند ۱ به‌دستِ اندازه‌گیریِ انسانی (خوانشِ README) پیدا شد، نه توسطِ این آزمون؛ آزمون فقط تکرارِ گونهٔ «اشاره به فایلِ منسوخ/حذف‌شده» را می‌بندد.
