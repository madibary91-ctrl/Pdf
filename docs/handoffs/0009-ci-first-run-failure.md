# یادداشت تحویل ۰۰۰۹ — رفع شکست نخستین اجرای CI

## گزارش اولیه و یافتهٔ واقعی
گزارش: «KB_TEST_DATABASE_URL or DATABASE_URL is required / vitest failed 1 test file».
بررسی اجرای واقعی (Actions run #1، کامیت `d2df401`) از طریق API عمومی گیت‌هاب:

| گام | نتیجه |
|---|---|
| Typecheck، Lint | ✅ |
| Gate self-check (کنترل منفی) | ✅ سبز — **همین‌جا** پیام «…لازم است» چاپ می‌شود (مورد انتظار) |
| Tests (zero-skip gate) | ❌ — preflight پایگاه موفق؛ «۱ تست/فایل شکست خورد؛ vitest کد ۱» |
| Build | ⏭️ رد شد (به‌خاطر شکست گام قبل) |

پس متغیر محیطی/پایگاه مشکل نبود؛ پایگاه در CI درست بود. پیام گمراه‌کننده از annotation قرمزِ کنترل منفی می‌آمد.

## محدودیت صادقانه
لاگ کامل و artifact گزارش به احراز هویت نیاز دارند و در دسترس من نبودند؛ **نام دقیق تستِ شکست‌خورده را ندیدم**. علتِ محتمل (استنتاج، بازتولیدشده زیر بار): مهلت پیش‌فرض ۵ ثانیه‌ای Vitest. با ۳ اجرای هم‌زمان روی یک ماشین، پیش از اصلاح «Test timed out in 5000ms» روی سه تست دیده شد؛ پس از اصلاح، هیچ timeout دیده نشد. (اجرای هم‌زمانِ چند مجموعه روی یک پستگرس به‌خاطر `max_connections` شکست‌های دیگری هم می‌سازد که مربوط به CI نیست — یک مجموعه در هر CI.)
اگر اجرای بعدی باز قرمز بود، **Step Summary/annotation اکنون نام تست و پیام را می‌گوید**؛ آن را برای من بفرستید.
