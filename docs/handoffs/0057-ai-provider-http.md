## ۱) چرا این برش (تصمیم من)
یادداشتِ ۰۰۵۵ گفت «محصولاً هنوز هیچ مدلِ واقعی ابزار را صدا نمی‌زند» و CT‑3c را گامِ بعد نوشت. بدونِ انتقالِ HTTP، حلقهٔ ابزار (CT‑4) هرگز به مدلِ واقعی نمی‌رسد. انتقال یک ناحیهٔ امنیتیِ جداست (کلیدِ API، SSRF، DoS)، پس ماژولِ جدا با `humanReview:true` (ADR‑0057). از برش‌های ممکن، «ارائه‌دهندهٔ HTTP (بی‌تماسِ زنده)» کوچک، مستقل از CT‑4 و قابل‌اثباتِ کامل با سرورِ loopback است؛ قراردادِ زنده (CT‑3c‑2) جداست چون کلیدِ واقعی می‌خواهد.
**سازمان‌دهیِ نوبت:** کلون و بررسیِ پایه ← کشفِ ناهمخوانی (بند ۰) ← تگِ پیش‌ازریسک ← طراحی ← کد+آزمون ← **جهش‌آزمایی** ← ثبت در registry و docs ← **یک دروازهٔ کاملِ صفر‌رد** ← کف ← مستند. در حینِ کار فقط آزمون‌های همین برش + `tsc` + `eslint`.

## ۴) یافته‌های واقعیِ این برش
1. **حفرهٔ امنیتی را آزمون گرفت:** `new URL("https:///v1")` بی‌صدا به میزبانِ `v1` ترمیم می‌شود (و `https:host`، `https:/host`) ⇒ کلید به میزبانِ اشتباه می‌رفت. اعتبارسنجیِ خامِ ورودی پیش از `URL` اضافه شد (ADR‑0057 بند ۵، pitfalls).
2. **جهشِ آزمون:** ۴۰ جهش در کدِ محصول (اسکریپتِ قطعیِ یک‌بارمصرف، در مخزن نیست): اجرای اول ۴ «بازمانده» ⇒ دو مورد آزمونِ ضعیف (لغوِ حینِ fetch به‌خاطرِ ترتیبِ microtask از مسیرِ پیش‌ازارسال می‌گذشت؛ مرزِ `content-length == سقف` آزموده نبود)، یک مورد جهشِ ناقص (نقطهٔ جهش در توضیحِ کد افتاده بود)، یک معادل. پس از اصلاحِ آزمون‌ها و بازاجرای هدفمند: **همه کشته**. همچنین اجرای اولِ آزمون‌ها نشان داد `Retry-After` برای `auth` هم منتقل می‌شد؛ اصلاح شد (فقط rate_limited/unavailable).
3. `Response` استانداردِ Node: وضعیتِ `304` با بدنه و `100` قابل‌ساخت نیست؛ آزمون‌ها از ۳۰۲/۳۰۷ و `redirected` استفاده می‌کنند.
