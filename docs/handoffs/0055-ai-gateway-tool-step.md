## ۱) چرا این برش و چرا «شکافتنِ قرارداد» را نکردم (تصمیم من)
ADR-0054 CT‑3b را «گسترشِ `ModelProvider`/`Completion` و تأییدِ معماری» نوشته بود. بررسیِ مصرف‌کننده‌ها نشان داد گسترشِ درجا کدِ خطای تازه، فیلدِ اختیاریِ `toolCalls` روی `Completion` و دست‌زدن به لایهٔ تاب‌آوری را هم‌زمان می‌خواهد (چند ماژولِ پرریسک)، و جایگزینیِ میان‌ارائه‌دهنده برای گفت‌وگوی ابزاری اصلاً معنا ندارد. پس **افزایشی و کنارِ قرارداد** ساختم (ADR-0055): نیازی به «تأییدِ معماری» نماند چون چیزی نمی‌شکند.
**سازمان‌دهیِ نوبت:** خواندنِ ۰۰۵۴/gateway/registry ← یافتنِ `tsc` قرمز و رفعِ آن ← طراحی ← کد ← آزمون ← جهش‌آزمایی ← **یک دروازهٔ کامل، یک‌بار، پس از آخرین تغییرِ کد** (۶ دقیقه، در پس‌زمینه با لاگ) ← کفِ دروازه ← مستند. تا آن‌جا فقط آزمون‌های همین برش، `tsc` و `eslint`.
