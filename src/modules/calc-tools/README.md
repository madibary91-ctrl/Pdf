# calc-tools (لایهٔ ۳ · خالص)

**هدف:** مرزِ امنِ «مدل ← محاسبه». توصیفِ ابزارهایی که مدل صدا می‌زند + اعتبارسنجیِ سخت‌گیرانهٔ آرگومان‌های نامطمئن + اجرای `legal-calc` + بسته‌بندیِ نتیجه.
**وابستگی:** `legal-calc` (فقط رابط عمومی) و `shared-types` (`Result`). بی‌I/O، بی‌ساعت، بی‌تصادف.
**برش ساخته‌شده (CT‑1، ADR-0053):** دو ابزار — `court_fee` (هزینهٔ دادرسی) و `late_payment` (خسارت تأخیر تأدیه). ارث (`inheritance`) برشِ CT‑2 است.

> ⚠️ هر دو ابزار روی جدول‌هایی کار می‌کنند که هنوز **تأییدِ حقوقدان ندارند**؛ `reviewPending` در هر خروجی `true` است و **ارکستراتور باید آن را کنار پاسخ به کاربر بیاورد**.
> این ماژول هیچ عددِ حقوقی (نرخ، آستانه، شاخص) ندارد؛ آزمونِ منبع این را قفل می‌کند.

## استفاده
```ts
import { CALC_TOOLS, executeCalcToolJson } from "@/modules/calc-tools";

CALC_TOOLS;                                   // توصیفِ ابزارها برای مدل (ژرف یخ‌زده، JSON-سازگار)
const r = executeCalcToolJson(name, argsJson); // name و رشتهٔ JSONِ آرگومان‌ها دقیقاً همان‌طور که مدل فرستاده
if (r.ok) {
  r.value.result;         // عیناً خروجیِ legal-calc (JSON-سازگار)
  r.value.reviewPending;  // true مگر «legally-verified» — باید به کاربر نمایش داده شود
  r.value.notes;          // هشدارهای فارسیِ legal-calc — باید کنار نتیجه نمایش داده شوند
} else {
  r.error.message;        // فارسی؛ می‌توان عیناً به مدل برگرداند تا آرگومان را اصلاح کند
}
```
`executeCalcTool(name, args)` همان است با آرگومانِ از‌پیش‌پارس‌شده.

## ناورداها
- **منبعِ حقیقتِ یگانه:** `CALC_TOOLS[i].parameters` هم چیزی است که مدل می‌بیند و هم قاعدهٔ اعتبارسنجی. آزمونِ توافق از روی خودِ شما برای هر کلید/برگ/enum موارد نامعتبر می‌سازد و رد‌شدن را می‌سنجد.
- **سخت‌گیری بی‌حدس:** کلیدِ ناشناخته رد؛ رشته به عدد تبدیل نمی‌شود (حتی «۱۰۰» با رقم فارسی)؛ اعشار/NaN/بی‌نهایت/بیش از ۲^۵۳ رد؛ دو منبعِ ناسازگار (`manual` همراه کلیدهای `series` و بالعکس، `known` همراه نبودِ مبلغ، `unknown` همراه مبلغ) رد. **`tierMethod` را هرگز حدس نمی‌زند** (قانون ساکت است).
- **بی‌پرتاب نسبت به ورودیِ مدل:** Proxy/getterِ بدجنس، JSONِ خراب یا بزرگ (> `MAX_ARGS_JSON_LENGTH`)، نامِ ابزارِ `__proto__`/`constructor` همه `Result` خطا می‌دهند (Map، نه شیءِ ساده). فازینگِ قطعی (seed ثابت) ۹۰۰۰ ورودی را می‌گذراند. *باگِ درونیِ legal-calc پنهان نمی‌شود* (try/catch دورِ محاسبه نیست).
- **بی‌سکوت:** خروجی با `toJsonValue` سخت‌گیرانه تبدیل می‌شود؛ NaN/بی‌نهایت/bigint به‌جای `null` شدنِ بی‌صدا ⇒ `OUT_OF_RANGE`.
- **خروجی عیناً legal-calc است** (آزمونِ تفاضلی روی شبکهٔ مرحله × مبلغ × روش × تاریخ، و برای خطاها `code` و `message` برابر). `review` و `notes` بالا آورده می‌شوند.
- **پیامِ خطا کران‌دار:** حداکثر ۱۰ مشکل، نامِ کلیدِ ورودی به ۴۰ نویسه بریده می‌شود.
- **تغییرناپذیر:** توصیفِ ابزار و خروجی ژرف یخ‌زده‌اند.

## محدودیت‌های شناخته‌شده
- مشخصاتِ حقوقیِ ورودی/خروجیِ مرجع از حقوقدان **نیست** (قاعدهٔ ۷): آزمون‌ها فقط پوششِ مرزی را می‌سنجند؛ درستیِ جدول‌ها با `legal-calc` و بازبینیِ حقوقدان است.
- حالتِ `series` در تأخیر تأدیه تا وقتی حقوقدان سری ثبت نکند همیشه خطا می‌دهد (در `legal-calc` هیچ سری ثبت نیست).
- آداپتورِ ارائه‌دهنده (تبدیلِ `CALC_TOOLS` به قالبِ OpenAI/Anthropic) و حلقهٔ ابزارِ ارکستراتور (ADR-0016 ردیف ۷‑۴) هنوز نیستند.
- توصیفِ ابزار از `oneOf` استفاده نمی‌کند (سازگاری با ارائه‌دهنده‌ها)؛ قاعده‌های میان‌فیلدی در کد و در پیامِ خطا به مدل گفته می‌شوند.
