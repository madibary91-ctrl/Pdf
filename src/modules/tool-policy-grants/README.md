# tool-policy-grants

CLIِ رسمیِ **حقوقِ نقشِ زمانِ اجرای** سیاستِ ابزار (CT‑5c‑2c‑4، ADR-0081): قراردادِ ایستا و بستهٔ «برنامه دقیقاً چه می‌تواند»، با سه فرمان — `plan` (چاپِ دستورها، بی‌اتصال)، `verify` (فقط‌خواندنی؛ سنجشِ **حقوقِ مؤثر** در برابرِ قرارداد) و `apply` (REVOKE/GRANTِ همگراکننده در یک تراکنش و **خواندنِ دوباره**) — با کدهای خروجِ بسته، گزارشِ JSONِ بی‌نشت و مهلتِ کل.

بسته‌شدنِ شکافِ ۰۰۷۹: مهاجرت‌دهنده شِما و جدول‌ها را می‌ساخت ولی «برنامه چه حقی بگیرد» نه مستند بود نه آزموده. اکنون قرارداد این است و با PostgreSQLِ واقعی و **نقشِ بی‌امتیاز** ثابت شده است.

## قراردادِ حقوق (کمترین امتیاز)
| شیء | حق‌های نقشِ زمانِ اجرا | چرا |
|---|---|---|
| شِما | `USAGE` | حلِ نامِ جدول‌ها (`to_regclass`). `CREATE` هرگز: برنامه DDL نمی‌زند |
| `tool_policy_versions` | `SELECT`، `INSERT` | `latest/get/list/status` می‌خوانند؛ `append` می‌نویسد؛ تریگرِ زنجیره `max(version)` را می‌خواند. `UPDATE/DELETE/TRUNCATE` هرگز: «فقط‌افزودنی» علاوه بر تریگر با **نبودنِ حق** هم اجرا می‌شود |
| `tool_policy_migration_ledger` | `SELECT` | `assertCurrent` دفتر را می‌خواند؛ نوشتنِ دفتر کارِ نقشِ مهاجرت است |

این فهرست از کدِ ذخیره‌ساز **اشتقاق** شده و آزمونِ PostgreSQLِ واقعی آن را از دو سو ثابت می‌کند: *کفایت* (ذخیره‌سازِ واقعی با نقشِ `-c role=…` همهٔ عملیاتش را انجام می‌دهد؛ UPDATE/DELETE/TRUNCATE/DDL/خاموشیِ تریگر/`session_replication_role` همه `42501`‌اند) و *ضرورت* (حذفِ هر یک از چهار حق ⇒ دستِ‌کم یک عملیاتِ ذخیره‌ساز می‌شکند و `verify` همان حق را `missing` می‌گوید).

## استفاده
```
npm run policy:grants -- plan   --role=policy_runtime                       # بی‌DATABASE_URL؛ دستورها را چاپ می‌کند (برای بازبینیِ DBA)
DATABASE_URL=… npm run policy:grants -- verify --role=policy_runtime         # فقط‌خواندنی؛ ۰ = دقیقاً قرارداد
DATABASE_URL=… npm run policy:grants -- apply  --role=policy_runtime [--timeout-ms=N]
```
`DATABASE_URL` رشتهٔ اتصالِ **نقشِ مدیر** (مالکِ شِما یا دارندهٔ GRANT OPTION) است؛ نقشِ زمانِ اجرا با `--role` نام برده می‌شود و باید از پیش وجود داشته باشد — این ابزار **نقش نمی‌سازد و رمز نمی‌گذارد**. شِما از `TOOL_POLICY_SCHEMA` (همارزِ bootstrap/migrate؛ نبودن = `tool_policy`). ترتیبِ استقرار: `policy:migrate up` ← (مدیر) `CREATE ROLE` ← `policy:grants apply` ← `policy:grants verify` (دروازه) ← راه‌اندازیِ برنامه.

## کدهای خروج
`0` قرارداد برقرار · `1` داخلی/پاسخِ بدشکل · `2` آرگومان/env · `3` شِما/جدول نیست (ابتدا `policy:migrate up`) · `4` پایگاه در دسترس نیست · `5` (فقط verify) حقِ کم/**زیاد** · `6` apply شکست خورد یا پس از اعمال هنوز ناهمخوان (مثلاً حقِ زیاد از PUBLIC/عضویت) · `7` مهلت · `8` نقش نیست/خطرناک/مالک است.

## چه چیزی می‌سنجد
**حقوقِ مؤثر** (`has_*_privilege`: شاملِ PUBLIC، عضویت و مالکیت) روی شِما و **همهٔ رابطه‌های شِما** (نما، دنباله… نه فقط جدول‌های شناخته‌شده): حقِ زیاد مثل حقِ کم خطاست. نقشِ `superuser/createrole/createdb/bypassrls/replication` یا مالکِ (یا عضوِ مالکِ) اشیای سیاست `ROLE_UNUSABLE` است و هیچ نوشتنی نمی‌شود (چنین نقشی تریگرِ فقط‌افزودنی را خاموش می‌کند).

## `apply` چه می‌کند
یک تراکنش، زیرِ قفلِ مشورتیِ کلید‌شده با شِما: `SET LOCAL lock_timeout/statement_timeout` (نیمِ مهلتِ کل) ← `REVOKE ALL` روی شِما، همهٔ جدول‌ها و همهٔ دنباله‌های شِما ← `GRANT` دقیقاً قرارداد. همگراست (idempotent و حقِ زیادِ قبلی را هم می‌برد). پیش از هر نوشتن: نقش، شِما و جدول‌ها سنجیده می‌شوند؛ پس از آن دوباره خوانده می‌شود و `ok` هرگز از ادعای خودش نیست.

## محدودیت‌های صادقانه
- `REVOKE` فقط حقِ مستقیمِ نقش را می‌برد؛ حقِ از راهِ PUBLIC یا عضویتِ نقشِ دیگر `APPLY_FAILED` می‌دهد و باید ریشه برداشته شود.
- `MAINTAIN` (PostgreSQL ≥ ۱۷) و حقِ `EXECUTE` روی توابعِ تریگر (پیش‌فرضِ PUBLIC) نه پرسیده می‌شوند نه برداشته؛ تریگر با حقِ فراخواننده اجرا می‌شود و تابع خودش فقط `max(version)` می‌خواند.
- `ALTER DEFAULT PRIVILEGES` و حقوقِ سطحِ پایگاه (`CONNECT`) دست‌نخورده‌اند (کارِ مدیر).
- مهلتِ سمتِ سرور نیمِ `--timeout-ms` است تا انتظارِ قفل معمولاً پیش از مهلتِ کلاینت در سرور برگردد؛ اگر شبکه کاملاً بی‌پاسخ شود، بک‌اندِ منتظرِ قفل تا سقفِ `lock_timeout`ِ جلسه (۶۰۰٬۰۰۰ms) می‌ماند و آنگاه همان دستورهای همگراکننده را (بی‌ضرر، idempotent) اعمال می‌کند.

## رابط عمومی
`runToolPolicyGrants({argv, env, ports:{open, query, transact, timer, write}})`، `parseGrantsArgs`، `planStatements`، `GRANTS_EXIT`، `RUNTIME_CONTRACT`، `CONTRACT_TABLES`. ماژول SQLِ اجرایی ندارد: متنِ ثابتِ پرس‌وجوها/دستورها را می‌سازد و پورت‌های گلو (`tooling/cli/grants-pg.ts`: `query` در `BEGIN READ ONLY`، `transact` در یک تراکنش) اجرایشان می‌کنند.
